# 15. Interview Questions About My Projects

## Q1. Explain RAG in simple terms.

RAG stands for Retrieval-Augmented Generation. Instead of asking an LLM to answer using only its internal knowledge, we retrieve relevant information from an external knowledge source and provide that information as context.

A typical pipeline includes document ingestion, chunking, embeddings, vector storage, retrieval, context construction, and LLM generation.

## Q2. Why do we need embeddings?

Embeddings represent text as numerical vectors. They allow us to compare the semantic meaning of a query and document passages, rather than relying only on exact keyword matches.

## Q3. Why did you use FAISS?

FAISS is a library for efficient similarity search over dense vectors. I used it in an RAG implementation to retrieve relevant document chunks based on vector similarity.

## Q4. Why use OpenSearch Serverless?

OpenSearch Serverless can provide scalable search and vector retrieval capabilities. In my Bedrock RAG work, I used it as the semantic retrieval layer for document-related queries.

## Q5. What is the difference between FAISS and OpenSearch?

FAISS is a vector similarity search library. OpenSearch is a search and analytics platform that supports vector search alongside other search capabilities.

They can both support retrieval, but their architecture, operational model, and capabilities differ.

## Q6. What is Amazon Bedrock?

Amazon Bedrock is an AWS service that provides access to foundation models and capabilities for building generative AI applications.

I have used it in RAG work involving embeddings and LLM-based answer generation.

## Q7. What is AutoGen?

AutoGen is a framework for building applications involving AI agents that can communicate and coordinate to complete tasks.

I have used it in the context of agent-based RAG workflows.

## Q8. Why Redis caching?

Redis caching helps avoid repeating expensive or unnecessary work by storing data that can be reused. It can reduce database load and improve response times when implemented with appropriate cache keys, expiration, and invalidation rules.

## Q9. What is rate limiting?

Rate limiting controls how frequently a client can call an API within a defined period. It helps protect services from excessive requests and provides more predictable resource usage.

## Q10. What is BullMQ?

BullMQ is a Redis-backed job queue for Node.js. It helps process background tasks asynchronously instead of making the user wait for every operation to finish in the request-response cycle.
